# Sarah Arcade

Menu: `/projects/sarah-arcade/`. Games have stable individual URLs: `/projects/sarah-jumps/` and `/projects/flappy-sarah/`.

`catalog.ts` is the list of games, routes, controls, descriptions, and storage keys. The menu, game page layout, and sharing use it. Sarah Jumps retains its original URL, physics, sprites, and `sarahJumpsHighScore` key. Flappy Sarah stores its score separately in `flappySarahHighScore`. Bests are local to the browser; the menu refreshes them on page-cache restores and cross-tab storage changes.

Shared high scores are provided by `scores.ts`, `leaderboards.ts`, and `Leaderboards.astro`. Every game ends with the shared `finish.ts` / `ScoreEntry.astro` screen: players submit three A–Z initials or skip posting, then see their best's rank on the all-time top-20 board. A run enters the durable sync queue only after initials are confirmed; skipped runs are never queued, and local bests still save immediately. Network failures allow replay and retry automatically. Existing longer nicknames remain readable. The arcade home flips all six cards to top-five rankings through `cabinets.ts`. See `workers/arcade/README.md` for API configuration, tests, deployment, and moderation.

`src/layouts/ArcadeGame.astro` and `game.css` provide the site-styled page, canvas, score display, pause/results panel, controls, and sound control. On portrait phones, a 48px header and 44px footer leave the rest of the dynamic viewport for an edge-to-edge playfield (plus safe-area insets). Touch controls act directly on the canvas; the separate button row is hidden. Sarah Jumps can start and steer from the same finger contact. Each game owns its input and simulation. Both use `FixedStepLoop`, safe score storage, and `GameAudio`. The shared audio reuses the existing files under `public/games/sarah-jumps/sounds/`.

To add a game:

1. Add its metadata and a unique best-score key to `catalog.ts`.
2. Add a route using `ArcadeGame` and a game instance with an explicit cleanup boundary. Extend the layout's input controls if the new game needs a different control scheme.
3. Implement its simulation independently of the DOM. Keep rendering at display refresh, physics in seconds, and a bounded live object count.
4. Add a static preview in `src/components/arcade/GamePreview.astro` and simulation/input checks in `scripts/arcade/`.

Both games keep a 400-unit world width and uniform drawing scale. A taller phone reveals extra course above Sarah Jumps' original camera without changing its physics or score scale. Flappy Sarah adapts its sky/floor height, moving Sarah and pipe gaps together when the viewport changes so a resize preserves the flight. Its classic-style tuning uses a roughly 41-pixel hop with a 0.22-second ascent, a constant 165 px/s scroll, 136-pixel gaps, and 230-pixel pipe spacing. Speed and gap size stay fixed as the score rises; pipe centers move by at most 75 world pixels between gaps. Pausing or backgrounding stops the animation loop. The game ignores key repeat and secondary touches. Retry is explicit.

Flappy Sarah combines a compact yellow bird body with the original Sarah Jumps head. `../flappy-sarah/Sprite.ts` reuses the original cap, face and ponytail pixels and caches four wing poses once at load. Each tap triggers an up/middle/down/recovery wing stroke, with the head and body fixed. The Arcade menu shares the same composition. Sarah Jumps retains its original sprites, rendered without smoothing. Previous sprite sets remain in the source assets, but there is no outfit UI or persisted choice. The asset README records the source and generation prompts.

## Validation

```sh
npm run test:arcade
npm run build
npm run preview -- --host 127.0.0.1 --port 4322
```

The checks include both games' refresh-rate independence at 30/60/90/120/144 Hz, 100 seeded 90-second courses per game across three viewport heights with mid-run resizes, collisions, scoring, bounded object counts, touch-to-start/drag, input cancellation/repeat, cleanup, and storage behavior.

With the dev server, `/projects/flappy-sarah/?playtest` exposes a local-only 30-second keyboard-driven endurance test and frame statistics. Sarah Jumps retains its equivalent `?playtest` harness. Neither is shipped in production. Manually verify mobile and desktop menu navigation, tapping, keyboard input, pause/resume, retry, and independent scores. Desktop viewport emulation does not establish physical iPhone performance.

## Collection games

The arcade also includes Sarah Skis, Crossy Sarah, Sarah Stacks, and Sarah Rolls. Their routes are statically generated by `src/pages/projects/[arcadeGame].astro`, using the same layout, score storage, pause UI, and original Sarah Jumps sprite. There are no new image-generation dependencies or remote game services.

`collection/` contains four independent DOM-free simulations, a canvas renderer, pointer/keyboard input, and a lifecycle controller. The 120 Hz shared loop drives seconds-based physics with one render per display frame. Resize only changes the camera framing, so the course and collision geometry survive rotation. Object lists are pruned and pixel ratio is capped at 2. Pausing or backgrounding stops simulation and rendering; held inputs are cleared. Retry uses the explicit results button to avoid accidental restarts.

- **Skis:** drag to steer, or hold left/right. After a gentle opening, distance gradually increases speed (225–420 units/second), tightens row spacing (230–180), narrows gates, and increases turns. The course reaches its capped difficulty around 100 seconds; generated rows stay fixed. Gates award bonuses, ramps clear trees, and consistent gates keep the pursuing yeti away after 30 seconds, with pursuit pressure increasing as the slope gets harder.
- **Crossy:** tap forward, swipe in any direction, or use arrows/WASD. Roads, moving logs, and warning-signaled trains alternate with safe banks. Waiting too long lets the camera catch up.
- **Stacks:** tap or press Space to drop. Overhang is trimmed; three perfect placements restore up to 16 units of lost width, capped at the original 190. The tower scrolls upward as Sarah climbs.
- **Rolls:** hold either half of the screen or left/right to roll; release to brake, or steer opposite your movement to brake harder. Orange springs launch automatically; golden springs boost across longer gaps. Courses alternate boost landings, wide platforms with low moving red gates, and striped ledges that crumble 0.85 seconds after landing. Gate markers turn green when there is time to cross. Regular platforms get shorter over the first 32 ledges, requiring speed control in the air. Three-star arcs reward taking the faster line: every three consecutive pickups increases the multiplier, up to ×5; missing one resets it. Star sparkles, a launch stretch, and a golden boost trail provide feedback.

`npm run test:arcade` includes 50 seeded runs per new game, fixed-step equivalence across 30/60/90/120/144 Hz, object-count limits, collisions, frozen game-over states, perfect-stack bonuses, and input cancellation/cleanup. Scripted pilots verify traversable ski, stack, and roll courses; the Crossy pilot can lose normally to traffic, water, or the time limit and is checked for progress rather than guaranteed survival. These simulations do not replace manual difficulty testing.

Skis also runs three-minute progression checks with drag and keyboard pilots across 50 seeds plus a course of maximum alternating turns without ramps. These cover capped speed, tighter spacing and gates, bounded objects, stable generated geometry, gate scoring, and yeti pressure. Its refresh-rate checks run for two minutes to include the full difficulty ramp.

Rolling snowballs begin around 19 seconds into Skis and alternate sides. Edge arrows warn up to two seconds before a crossing, and the ball follows a fixed diagonal path without tracking the skier. Each crossing gets a 360-unit clearing between tree gates to allow a dodge and recovery. Crossings get more frequent with distance; ramps clear snowballs as well as trees. Snowball collision, airborne immunity, direction, frozen game-over state, and clearing space are included in the progression checks.

Rolls checks also cover 50 three-minute seeded courses with repeated boosted jumps, reachable star multipliers, chain resets, one-time pickups, automatic launches, timed gates, crumbling floors, braking, and bounded effects. A separate full-throttle pilot must lose at least 40 of 50 courses within a minute, while the adaptive pilot must survive all 50. Gate platforms are always wide and never crumble; platforms after golden springs have no bumper, giving boosted landings room to recover.

Rolls uses color, motion, and sound for in-game cues rather than word labels or popup messages. Crumbling platforms are thin, striped slabs with open space beneath them; only solid platforms extend down to the bottom of the scene. The score and numeric multiplier remain visible.

Each new route supports a development-only `?playtest` mode with a 15-second control test (45 seconds for Skis and Rolls to include their course challenges) and frame statistics. The harness drives the real keyboard handlers and does not ship in production. Use browser testing for pointer drag, swipe, hold/release, pause, retry, score persistence, and layout; physical iPhone responsiveness remains a user acceptance check.
